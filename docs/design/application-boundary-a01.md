# A01 — Inventory và Python application boundary

Ngày chốt: **2026-09-23**. Đây là contract để review trước A02–A04, chưa phải API đã triển khai. Nguồn: `novel_ai_spec_v0.2.md`, `MILESTONE_A_REFACTOR_PLAN.md`, D016–D019, `schemas.md`, `storage.md`, source của 9 page và báo cáo T40 mục 3. Tên command/query dưới đây là **tên đích đề xuất**, không tuyên bố đã có hàm tương ứng.

## 1. Quy ước inventory

- Mọi query/command có `project_id` là stable ID trong `project.json`; adapter không nhận path tùy ý từ client. Query danh sách project dùng `projects_root` từ cấu hình app, không nhận root từ request. `artifact_id`, `arc_id`, `chapter_id`, `revision` là định danh/phiên bản cụ thể.
- Cột **Ghi**: `Ø` = không ghi; `C` = candidate/raw hoặc report; `A` = accepted artifact; `P` = `project.json`; `D` = draft/chapter metadata; `F` = final manuscript + state; `H` = history/stale/operation manifest. Một action có thể ghi nhiều loại. `C` không biến thành canon nếu chưa Accept; Auto Accept structured hợp lệ có thể thêm `A` trong cùng action generation.
- Cột **Guard**: `pin` = dependency revision/fingerprint; `base` = expected candidate/prose revision hoặc payload fingerprint từ form; `scope` = horizon/arc/chapter/effective chapter; `chain` = chapter lifecycle + previous `final_reconciled`; `lock` = pending operation/read-only. **Mọi write thông thường** phải kiểm `lock`; recovery là ngoại lệ có chủ đích để xử lý chính pending/lock đó. Idempotency qua `operation_id` ở backend. `operation_id` có thể do adapter sinh nhưng application/service phải nhận hoặc cấp và trả lại; replay cùng ID + cùng intent không ghi/merge/gọi LLM lần hai. Cùng ID nhưng intent khác là lỗi. Những guard trong bảng là phần đặc thù thêm vào nền này.
- Cột **Event**: `G` = `GenerationEvent` lifecycle; `—` = không generation event. Action không LLM trả terminal command result nhưng không giả event `saved` của generation. UI click, spinner, navigation, reload editor, tab, preview và transcript cache là session action, không phải mutation backend.
- Cột **Test** trỏ tới file hiện có kiểm đường liên quan; **không** khẳng định mọi nhánh trong hàng đã có contract test riêng. A03/A05 sẽ thêm contract tests theo boundary mới.

## 2. Python contract đích

```python
class Application:
    def query(self, request: Query, *, scope: ProjectScope) -> QueryResult: ...
    def execute(self, command: Command, *, scope: ProjectScope,
                on_event: Callable[[GenerationEvent], None] | None = None) -> CommandResult: ...

# ProjectScope: configured projects_root + validated project_id; no caller-supplied path.
# Query/Command: tagged, versioned Python dataclasses/Pydantic models, explicit fields.
# Command: operation_id, expected_revision/fingerprint where the action needs them.
# CommandResult: operation_id, IDs, revision/status, safe data, warnings, recovery flag.
# QueryResult: read DTO + read_only/recovery_required + revision/fingerprint token.
# ApplicationError: code, message, issues[{path, code, message}], operation_id?,
#                   current_revision?, retryable, recovery_required;
#                   no raw exception, secret, internal path.
```

Boundary đích dùng Python trong process; không đặt endpoint/HTTP status/SSE/WebSocket ở A. Không tạo `application` wrapper 1:1 cho mọi service. A02 gom read model/Arbiter/bootstrap, A03 gom command dispatch, error/result/event projection và dependency injection, A04 đổi adapter Streamlit. `core` giữ models/validation/storage/context/prompt/LLM, `services` giữ guard và mutation. `application`, `core`, `services` không import `ui`/`pages`/Streamlit; adapter chỉ gọi xuống. `Project` object/path/LLM client/PromptRegistry là dependency nội bộ, không là DTO công khai.

**Dependency wiring.** Application factory nhận `AppConfig` đã load, `projects_root` cố định, `PromptRegistry.load(config.prompt_root, repo_root=config.repo_root)` theo manifest v1, và `LLMClient` đã cấu hình từ `use_fake_llm` hoặc OpenAI-compatible config. Client/registry tạo một lần có thể cache theo config trong process, nhưng không gọi provider khi dựng, query hay render. Thiếu config/manifest trả capability/error redacted; chỉ explicit `probe_llm` hoặc generation command gọi provider. Service hiện có chỗ tự load registry qua repo root; A03 chuẩn hóa injection mà không đổi prompt text/selection. Test inject FakeLLM và registry fixture; không đọc `.env` thật.

**Guard/identity.** Validate project ID trong configured root, artifact/chapter/arc IDs và input schema trước service. Service/core vẫn quyết định authority, lifecycle, freshness, context projection, horizon và `effective_from_chapter`. Command giữ `expected_revision` hoặc fingerprint từ query, so ngay trước mutation; candidate pins/fingerprints và storage manifest so thêm ngay trước commit. Không chỉ dựa vào UI state signature hay disabled button. `stale_candidate`/`stale_dependency` trả current revision token để client reload; không tự merge working copy cũ. Những service hiện chưa nhận `expected_revision` trực tiếp (ví dụ một số Accept, `Project.update_config`) cần seam/concurrency guard ở A03 trước khi A04 chuyển page; kiểm lại sau reload, không đổi schema file.

**Errors.** Chuẩn hóa `ServiceError.code`/`details`, `ValidationResult.errors`, `StorageError.code`, `ProjectError`, `ConfigError`, `PromptError`, `LLMError` thành `ApplicationError`. Mã tối thiểu: `invalid_input`, `validation_failed`, `guard_failed`, `stale_candidate`, `stale_dependency`, `recovery_required`, `project_not_found`, `llm_unavailable`, `configuration_error`, `internal_error`. Giữ mã service cụ thể đã ổn định (ví dụ `missing_planning_scope`, `missing_writing_contract`, `invalid_outline_contract_item`) trong `code` hoặc `issues`; không bắt client parse lời nhắn. `retryable` chỉ đúng khi retry cùng intent/ID an toàn; lỗi sau khi gửi provider mà trước phản hồi có kết quả không chắc chắn, nên không hứa provider at-most-once. Không đưa raw prompt, header, key, full author truth, traceback, absolute path vào error/DTO/event.

**Event/terminal.** Giữ `core.generation.GenerationEvent`: `operation_id`, `action`, `attempt`, `transport`, `prompt_id`, IDs, status, raw preview/ref có giới hạn. `raw_ref` ra client phải là tham chiếu opaque hoặc đường tương đối đã kiểm tra quyền, không là absolute path. State `connecting → streaming|non_streaming → transport_complete → validating → saved|partial|invalid|error` (có replay `idle → saved`). `saved` là terminal thành công duy nhất, chỉ sau validate và persist kết quả phù hợp: candidate/draft/report hoặc raw record đối với `reviewer.rewrite_section`, nơi replacement chỉ trả trong result và chờ Apply riêng. `partial|invalid|error` là terminal lỗi, không mở Accept/Review/Finalize. Mọi generation command phải có đúng một terminal event nếu đã bắt đầu operation; lỗi guard xảy ra trước generation trả `ApplicationError`, không giả `saved`. Command result chỉ được trả thành công sau terminal `saved`; event và result cùng `operation_id`. Client giữ transcript scope `project_id|workspace|artifact_id|revision/operation_id`; disk giữ raw/partial/history. Không tự fallback sau stream dở. Retry là command tường minh với cùng ID để replay thành công, hoặc `attempt` mới/ID mới khi user chủ ý tạo request khác.

**Compatibility/recovery.** Không migration trong A. Đọc project cũ thiếu default POV/length như chuỗi rỗng, Long Plan thiếu `planning_scope` là legacy read-only đối với action cần horizon; `confirm_planning_scope` là mutation tường minh. File JSON/Markdown, envelope, stable ID, `effective_from_chapter`, `.ops` manifest, snapshot/history và raw refs giữ nguyên. Query pending operation chỉ trả recovery/read-only; `recover_project` là explicit command, kiểm manifest/hash, retry an toàn và không merge hai lần. Finalize tạo final candidate; chỉ Accept reconciliation commit nhiều file thành công mới làm chapter `final_reconciled`/mở chương sau. Writer DTO chỉ chứa projection an toàn theo chapter; author truth/future plot không được lọt vào Writer request, transcript hay view DTO dành cho Writer. Adapter chủ sở hữu project có thể xem editor author-only phù hợp, nhưng không trả nguyên context Writer hoặc prompt/debug secret qua query tổng hợp.

## 3. Gaps được A02–A04 xử lý

1. `ui/layout.py` hiện dựng config, prompt registry, client và probe; `ui/arbiter.py` + `ui/project_tree.py` chứa read rule thuần Python xen render. A02 chuyển phần read/bootstrap sang `application`.
2. `pages/short_plan.py::_render_writing_defaults` gọi `Project.update_config` trực tiếp; A03 thêm command `save_writing_defaults`, A04 đổi UI gọi command. Các page khác gọi service trực tiếp; A04 đổi sang application command mà giữ widget flow.
3. `pages/_chapter_ui.py::stable_operation_id` và `run_action` hiện là UI convenience. A03 chuẩn hóa replay/idempotency/revision tại boundary/service; A04 vẫn có thể dùng session guard để giảm double click nhưng không được coi là bảo vệ dữ liệu.
4. `services/__init__.py::ActionResult`/`ServiceError` và `core/generation.py::GenerationEvent` đã tồn tại. A03 chuẩn hóa safe projection thay vì đổi file storage/schema; A05 kiểm import direction, walkthrough và file compatibility.
5. `reviewer.rewrite_section` hiện trả replacement trong `ActionResult.data` và page giữ candidate trong session; raw output được lưu nhưng service chưa có replay theo `operation_id` như các action đã ghi candidate. A03 phải định nghĩa replay bền cho kết quả này hoặc trả lỗi `retry_result_unavailable` sau restart thay vì âm thầm gọi provider lần hai với cùng ID. UI click guard không giải quyết crash/restart. Tương tự, `Project.update_config` hiện tự sinh ID và không nhận expected fingerprint; command mới phải kiểm stale form trước ghi.
